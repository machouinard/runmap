### 2. Schema Standardization ✅

**Problem**: Activity tables (`runs_raw`, `walks_raw`, `cycling_raw`) had different columns:
- `runs_raw` had: `start_time`, `distance_km`, `metadata`
- `walks_raw` had: `avg_pace_min_per_mile`, `total_distance_m` (missing others)
- `cycling_raw` had: `avg_speed_mph`, `total_distance_m` (missing others)

**Solution**: Standardized all three tables to identical schema:
```sql
ALTER TABLE runmap.walks_raw 
  ADD COLUMN IF NOT EXISTS start_time TIMESTAMPTZ,
  ADD COLUMN IF NOT EXISTS distance_km NUMERIC,
  ADD COLUMN IF NOT EXISTS metadata JSONB,
  DROP COLUMN IF EXISTS avg_pace_min_per_mile;

ALTER TABLE runmap.cycling_raw
  ADD COLUMN IF NOT EXISTS start_time TIMESTAMPTZ,
  ADD COLUMN IF NOT EXISTS distance_km NUMERIC,
  ADD COLUMN IF NOT EXISTS metadata JSONB,
  DROP COLUMN IF EXISTS avg_speed_mph;
```

**Result**: All three tables now have identical structure. Activity-specific metrics can go in `metadata` JSONB if needed.

### 5. Run Buffering ✅

**Initial Attempt Failed**: Used `runmap.buffer_one_run()` function which:
- Applies highway-specific buffer distances (12-20m depending on road type)
- Loops through nearby blocks per run
- Extremely slow: 0 buffers after 5+ minutes

**Successful Approach**: Direct bulk INSERT with uniform buffer:
```sql
INSERT INTO runmap.runs_buffered_32610 (run_id, geom)
SELECT 
  id as run_id,
  ST_Buffer(ST_Transform(geom, 32610), 15.0) as geom
FROM runmap.runs_raw;
```

**Results**:
- **Duration**: ~1.5 minutes
- **Buffered**: 311 runs
- **Buffer distance**: 15m (default from `buffer_config`)

**Note**: Highway-specific buffering (12-20m per road type) needs performance optimization later. Uniform 15m is acceptable for now.

### 6. Coverage Calculation ✅ (FIXED)

**Initial Approach (WRONG)**: Intersect each run buffer with block, then union the LineStrings:

```sql
-- ❌ WRONG - Double counts overlapping coverage
ST_Union(ST_Intersection(b.geom_32610, rb.geom))
```

**Problem**: When a block is intersected by multiple runs, `ST_Union` creates a MultiLineString with overlapping segments that get counted separately by `ST_Length()`.

**Root Cause**:
```
Block 831 (11.6m total) intersected by 70+ runs:
- Each run creates a separate LineString segment
- ST_Union(LineString, LineString, ...) → MultiLineString
- ST_Length(MultiLineString) sums ALL segments
- Result: 817m for an 11.6m block (7050%!)
```

**Attempted Fix #1**: `ST_LineMerge` to collapse segments
- **Result**: Still 7050% ❌
- **Why it failed**: GPS tracks have coordinate variations, segments don't share exact endpoints

**CORRECT SOLUTION ✅**: Union the buffer **polygons** first, THEN intersect with block:

```sql
INSERT INTO runmap.block_coverage_32610 (block_id, covered_geom, covered_length_m, total_length_m)
SELECT
  b.block_id,
  ST_Intersection(b.geom_32610, ST_Union(rb.geom)) as covered_geom,
  ST_Length(ST_Intersection(b.geom_32610, ST_Union(rb.geom))) as covered_length_m,
  b.block_length_m as total_length_m
FROM runmap.streets_blocks_32610 b
JOIN runmap.runs_buffered_32610 rb ON ST_Intersects(b.geom_32610, rb.geom)
GROUP BY b.block_id, b.block_length_m, b.geom_32610;
```

**Key Difference**:
- `ST_Union(rb.geom)` - Unions the **polygon buffers**, creating a single merged coverage area
- `ST_Intersection(block, unified_polygon)` - Returns a single LineString (or MultiLineString without duplicates)
- No double-counting of overlapping coverage!

**Results After Fix**:
- **Duration**: <1 minute
- **Blocks with coverage**: 2,238 out of 2,597 total blocks (86.2%)
- **Complete blocks (≥90%)**: 1,932 (74.4% completion) ✅
- **Incomplete blocks (<90%)**: 306 (averaging 34.9% coverage)
- **Overall coverage**: **90.95%** ✅ (was impossible 130%)

## What Didn't Work

### ❌ Ultra-Fast Bulk Import Strategy
- Imports metadata without geometry, adds geometry later
- Adds complexity (two-phase process)
- Only saves 5-10 minutes vs fast method
- **Conclusion**: Not worth it for 600 files

### ❌ Sequential Per-Run Coverage Processing
- `rebuild_block_coverage()` function processes runs one at a time
- Causes locks, takes 30+ minutes, hangs without progress
- **Better**: Bulk GROUP BY approach (<1 min)

### ❌ Highway-Specific Buffer Function
- `buffer_one_run()` loops through blocks per run
- Missing spatial indexes cause full table scans
- Takes >5 seconds per run (25-50 min for 311 runs)
- **Better**: Simple uniform buffer (1.5 min for 311 runs)

### ❌ ST_LineMerge for Overlapping Coverage
- Doesn't merge lines with coordinate variations
- GPS tracks never have exact matching endpoints
- **Solution Found**: Union polygons first, then intersect (see section 6)

## Key Learnings

### What Worked Well ✅

1. **Bulk GROUP BY approach for coverage**: <1 minute vs 30+ minutes sequential
2. **Uniform buffer distances**: 1.5 minutes vs 25-50 minutes with complex logic
3. **Schema standardization**: Clean architecture, easier to maintain
4. **Progress logging**: Essential for long operations, prevents anxiety
5. **Server specs check**: Knowing 31GB RAM informed strategy decisions

### What to Avoid ❌

1. **Deferred geometry import**: Complexity not worth 5-10 min savings
2. **Sequential processing with transactions**: Causes locks and hangs
3. **Complex spatial functions in loops**: Performance killer
4. **Assuming documentation is current**: Always verify (RAM was wrong)
5. **Leaving bugs "for later"**: Fix issues before moving forward

### Process Improvements

1. **Always verify first**: Check schemas, test with small datasets
2. **Add progress feedback**: Long operations need visibility
3. **Use bulk operations**: GROUP BY > loops for large datasets
4. **Keep it simple**: Uniform buffers > highway-specific for first pass
5. **Document as you go**: This file captures context for future debugging
